    1) Что означает static¶

    • static привязывает поле/метод/класс не к объекту, а к самому типу.
    • Доступ к ним идёт через имя класса: Тип.поле, Тип.метод().
    • В static-методе нет this: он не видит нестатические поля/методы, пока вы явно не создадите/не передадите объект.

    Комментарий: думайте о static как о «общих для всех экземпляров» вещах — константы, функции-утилиты, фабричные методы, единые справочные таблицы.

    2) Где допустим static¶

    1. Поля — общие значения для класса (константы, статические счётчики, реестры).
    2. Методы — функции «без объекта»: преобразования, парсинг, проверки, main.
    3. Статические блоки инициализации — единоразовая подготовка статических полей.
    4. Вложенные классы (static nested) — вложенный тип без связи с экземпляром внешнего.
    5. Интерфейсы — статические методы и константы интерфейса.
    6. import static — подключение статических членов без префикса имени класса.

    3) Статические поля¶

    3.1. Константы¶

    • Объявляйте константы как public static final.
    • Константой считаются примитивы и String, у которых инициализатор — константное выражение (например, литерал или арифметика над литералами).
    • Важный эффект: такие значения встраиваются в байткод использующего класса при компиляции (см. §3.3).

    Комментарий: храните в константах именно стабильные семантические значения — форматы, единицы, пределы, коды.

    3.2. Общие справочники и флаги¶

    • Можно держать неизменяемые справочные коллекции: например, набор поддерживаемых MIME-типов.
    • Если значение может меняться между версиями библиотеки, избегайте «компилируемых констант» (см. ниже) — инициализируйте поле не «чистым» константным выражением, а результатом метода/конкатенацией переменных, чтобы клиент не вшивал его навсегда.

    3.3. Встраивание значений («constant folding / inlining»)¶

    • Если внешняя библиотека объявила public static final int X = 5;, ваш код при компиляции подставит число 5.
    • Если в библиотеке потом поменяли X = 6, а ваш код не перекомпилировали, он по-прежнему видит 5.

    Комментарий: это легко забыть. Для публичных «констант, которые могут меняться» — делайте инициализатор не константным ( например, считайте из другого static final не-константного типа), чтобы значение не встраивалось.

    3.4. Наследование и сокрытие¶

    • Статические поля «наследуются», но при совпадении имён в потомке скрываются (а не переопределяются).
    • Обращайтесь к ним квалифицированно: Родитель.CONST или Потомок.CONST, чтобы было ясно, откуда значение.

    4) Статические методы¶

    4.1. Назначение¶

    • Утилиты: валидаторы, конвертеры, форматтеры.
    • Фабрики: of(...), from(...), parse(...).
    • main: точка входа public static void main(String[] args).

    4.2. Важные свойства¶

    • В static-методе нельзя обращаться к нестатическим членам без экземпляра.
    • Статические методы не полиморфны: «одноимённый» метод в подклассе скрывает метод родителя, а не переопределяет. Выбор метода идёт по статическому типу ссылки в месте вызова.

    Комментарий: вызывайте статические методы через имя класса, а не через переменную-экземпляр — так код прозрачнее и не создаёт ложного ожидания полиморфизма.

    5) Статические блоки и порядок инициализации¶

    5.1. Когда класс инициализируется¶

    Инициализация класса происходит при первом активном использовании:

    • обращение к не-константному статическому полю,
    • вызов статического метода,
    • создание экземпляра (new),
    • отражение (reflection) и др.

    Замечание: обращение к компилируемой константе (см. §3.1) не инициализирует класс — значение уже встроено при компиляции.

    5.2. Порядок инициализации¶

    • Статические поля и статические блоки выполняются в текстовом порядке объявления сверху вниз.
    • Сначала инициализируются статические члены родителя, затем — потомка.

    5.3. Ошибки инициализации¶

    • Исключение в статическом блоке/инициализации приведёт к ExceptionInInitializerError.
    • После неудачной инициализации повторный доступ может дать NoClassDefFoundError.

    Комментарий: держите статическую инициализацию короткой и безопасной: проверяйте входные данные, избегайте тяжёлых действий (например, чтения с диска) прямо в статических блоках.

    6) Вложенные классы и static¶

    6.1. static nested class¶

    • Вложенный класс, не привязанный к экземпляру внешнего. По сути — «обычный» класс, сгруппированный по смыслу внутри внешнего.
    • Доступен как Внешний.Вложенный. Может иметь свои статические члены.

    Пояснение: выбирайте такой вариант по умолчанию, если хотите просто «сгруппировать» типы и не нуждаетесь в доступе к полям конкретного внешнего объекта.

    6.2. Внутренний класс (без static) — для контраста¶

    • Имеет неявную ссылку на экземпляр внешнего класса; создать его можно только «изнутри» объекта внешнего.
    • Из static-контекста (например, из static-метода) такой класс создать нельзя без явного экземпляра внешнего.

    7) static в интерфейсах¶

    • Любые поля интерфейса по умолчанию — public static final (константы).
    • Интерфейс может содержать static-методы — это утилиты контракта. Вызываются как ИмяИнтерфейса.метод().
    • default-методы — не static; это экземплярные методы с реализацией по умолчанию внутри интерфейса (упоминаем лишь для разграничения терминов).

    Комментарий: удобно складывать в интерфейс общие константы и тесно связанные с контрактом статические проверки/фабрики, но не переносите туда изменяемые настройки.

    8) import static¶

    • Позволяет использовать статические члены без префикса класса:

      • Пример идеи: подключить requireNonNull, PI, assertThat и т.п., чтобы записи были короче.
      • Плюсы: уменьшает «шум», удобно в формулах и тестах.
      • Минусы: может размывать источник символов — сложнее понять, откуда берётся имя.

    Рекомендация: использовать умеренно; в учебном/математическом/тестовом коде — отлично, в большом продакшен-коде — отдавать приоритет явности.

    9) Где static уместен¶

    • Константы домена: размеры, коды, форматы дат, единицы измерения.
    • Функции-утилиты: проверки входных данных, парсинг, форматирование, конвертация.
    • Фабричные методы: удобные конструкторы без new, если хотите контролировать создание.
    • Единые справочники: неизменяемые коллекции, доступные всем частям программы.
    • Главный вход: main.

    Комментарий: держите такие члены «чистыми» — без зависимостей от внешнего окружения и без скрытых побочных эффектов.

    10) Типичные ошибки и как их избежать¶

    1. Вызывают статические методы через переменную экземпляра. Лучше Класс.метод(): так видно, что это статический вызов и не предполагается полиморфизма.

    2. Ожидают, что статический метод «переопределится» в подклассе. Статика не участвует в динамическом выборе реализации — это сокрытие, а не переопределение.

    3. Слишком тяжёлая статическая инициализация. Большие вычисления, I/O, сложные проверки прямо в статическом блоке — риск ошибок инициализации и «тяжёлого» старта класса.

    4. Публичные «меняющиеся» константы. Если значение потенциально изменится в новой версии библиотеки, не делайте его компилируемой константой — иначе клиенты не увидят обновление без перекомпиляции.

    5. Складывают в статику то, что должно жить в объекте. Например, параметры конкретного экземпляра или результаты его работы. Такие вещи должны быть нестатическими полями/методами.

    6. Чрезмерный import static. Когда весь код в коротких именах без префиксов, теряется читаемость. Подключайте точечно — только действительно часто используемые элементы.

    11) Короткая шпаргалка¶

    • static привязывает член к классу, не к объекту; this недоступен.
    • Статические методы не полиморфны; вызывайте их через имя класса.
    • Инициализация класса запускается при первом активном использовании; статические блоки/поля выполняются в текстовом порядке.
    • Поля интерфейсов — всегда public static final; статические методы интерфейса вызываются как Интерфейс.метод().
    • import static сокращает записи, но может ухудшать читаемость — используйте умеренно.
    • Для публичных значений, которые могут меняться, избегайте компилируемых констант.
