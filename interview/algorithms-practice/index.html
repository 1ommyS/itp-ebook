    Алгоритмы и coding-задачи¶

    Стратегия на интервью¶

    1. Перескажите задачу и уточните вход, выход и ограничения.
    2. Назовите простой корректный вариант.
    3. Найдите узкое место и выберите структуру данных.
    4. До кода проговорите инвариант алгоритма.
    5. Проверьте пустой ввод, один элемент, дубликаты, overflow и границы.
    6. Оцените time и space complexity.

    Сильное решение — это не только код, но и доказательство его корректности на уровне инварианта.

    Big O¶

    Big O описывает верхнюю границу роста затрат, а не точное время. Для вложенных циклов сложность не всегда O(n²): если два указателя суммарно проходят массив один раз, это O(n).

    Рост Типичный пример
    O(1) доступ по индексу массива
    O(log n) бинарный поиск
    O(n) один проход
    O(n log n) эффективная comparison sort
    O(n²) сравнение всех пар

    Учитывайте дополнительную память, глубину рекурсии и амортизированную стоимость, например resize динамического массива.

    Паттерны¶

    Two pointers¶

    Подходит для отсортированных массивов, пар, удаления дубликатов и разворота. Инвариант: область вне указателей уже обработана.

    Sliding window¶

    Окно поддерживает агрегат на непрерывном диапазоне. Правый край расширяет окно, левый восстанавливает условие. Частая ошибка — забыть обновить ответ до/после сжатия в соответствии с задачей.

    Hashing¶

    Map/set меняет повторный линейный поиск на средний O(1), расходуя O(n) памяти. Для Two Sum храните уже увиденное и ищите дополнение.

    Monotonic stack¶

    Стек поддерживает монотонный порядок кандидатов. Каждый элемент входит и выходит не более одного раза, поэтому типичный алгоритм O(n), хотя внутри есть while.

    DFS и BFS¶

    • DFS естественен для компонент, backtracking и postorder-вычислений.
    • BFS на невзвешенном графе находит кратчайший путь по числу рёбер.
    • Пометка visited при добавлении в очередь обычно предотвращает дубликаты лучше, чем пометка при извлечении.

    Для дерева visited не нужен, если переходы только от родителя к детям. Для общего графа — нужен.

    Dijkstra¶

    Работает с неотрицательными весами. Priority queue хранит кандидатов; устаревшую запись можно пропустить, если её distance больше уже известной. С binary heap сложность обычно O((V + E) log V).

    Binary search¶

    Ищите не только значение, но и границу монотонного предиката: первый подходящий, последний допустимый, минимальный feasible answer.

    static int lowerBound(int[] a, int target) {
    int left = 0, right = a.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (a[mid] < target) left = mid + 1;
        else right = mid;
    }
    return left;
}

    Инвариант: ответ всегда находится в полуинтервале [left, right].

    Сортировки¶

    Алгоритм Среднее Худшее Доп. память Стабильность
    QuickSort O(n log n) O(n²) O(log n) stack в среднем Нет
    MergeSort O(n log n) O(n log n) O(n) Да

    На интервью важнее объяснить partition/merge, границы и trade-offs, чем воспроизвести библиотечную реализацию JDK.

    Heap и trie¶

    Heap полезен для top K, scheduling и слияния отсортированных потоков. Получение вершины O(1), вставка/извлечение O(log n); произвольный поиск не становится быстрым.

    Trie индексирует строки по префиксу. Время операции зависит от длины ключа, но структура может потреблять много памяти; alternatives — sorted array + binary search, compact trie или специализированный индекс.

    Практические задачи из чек-листа¶

    LRU cache¶

    Нужны HashMap<K, Node> и двусвязный список порядка использования. get и put должны быть O(1). Сформулируйте поведение capacity 0, обновления существующего ключа и thread safety.

    Thread-safe counter¶

    Сравните synchronized, AtomicLong и LongAdder. LongAdder хорошо масштабируется при высокой конкуренции, но sum() не является единым линейризуемым snapshot для составного протокола.

    Producer/consumer¶

    Используйте BlockingQueue, определите bounded capacity, завершение consumer, обработку interruption и backpressure.

    Rate limiter¶

    Token bucket хранит число токенов и время последнего refill. Нужны монотонные часы, атомарное обновление, ограничение burst и политика для распределённого режима.

    TTL cache¶

    Определите lazy или eager eviction, источник времени, максимальный размер, конкуренцию и поведение при одновременной загрузке одного ключа (cache stampede).

    REST endpoint¶

    Покажите DTO, валидацию, idempotency для повторяемой команды, корректные status codes, единый error contract и тест границы.

    Kafka consumer¶

    Отделите business retry от инфраструктурного, коммитьте offset после успешного эффекта, обеспечьте idempotency и определите DLQ с наблюдаемостью.

    SQL-задача¶

    Умейте совместить JOIN, aggregation и window function, объяснить обработку NULL и предложить индекс под фактический predicate/order.

    Чек-лист проверки кода¶

    • Имена отражают роль, а не тип (windowStart, не i).
    • Нет скрытого quadratic поведения.
    • Контракт для null/пустого ввода ясен.
    • Arithmetic overflow рассмотрен.
    • Mutable state минимален.
    • Complexity названа отдельно для времени и памяти.
    • Есть 3–5 тестовых примеров, включая границы.
